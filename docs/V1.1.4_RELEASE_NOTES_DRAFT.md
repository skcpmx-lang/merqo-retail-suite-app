## What’s new

**Server / Client model (the headline feature).** One shop database on one Main PC, and any number
of Client PCs that use it over the shop’s own encrypted network link. No shared folder, no SQLite
over SMB, no second copy of the books.

- **Main PC / Client PC roles** with an explicit setup choice; the Client PC holds no business
  data and cannot answer shop queries from its own file.
- **Device pairing with administrator approval**: a new PC shows up as *pending* and can do
  nothing until an admin approves it on the Main PC. Pairing codes are single-use and expire.
- **TLS with certificate pinning**: a Client refuses a server whose certificate does not match the
  pin it was paired with — a different machine on the same network cannot impersonate the Main PC.
- **Device identities (Ed25519) and device-bound sessions**, with instant revocation: revoking a
  PC closes its live connection and kills its session immediately.
- **Replay protection that survives a restart**, so a captured request cannot be replayed after
  the Main Server restarts.
- **Offline is honest**: while the Main PC is unreachable, the Client cannot sell. Nothing is
  queued to commit later behind the cashier’s back.
- **Live updates**: sales, stock, prices and payments made on any PC refresh the relevant screens
  on the others, through normal permission-checked reads. A missed or duplicated event only
  delays a refresh; it never injects data.

**POS stale-price and stale-stock protection.** If a price or stock level changes while an item
is sitting in an unsent cart, the line is marked `• যাচাই করুন` and the cashier can review the
change. Committing that cart is refused by the Main PC with a conflict naming the affected lines —
the price is never silently swapped, the cart is never emptied, and nothing is sold. Two tills
cannot sell the same last unit; a refused sale leaves no sale row, no payment, no stock movement
and no consumed invoice number.

**Hardening**

- Single database boundary: one place opens SQLite; client files are role-stamped and both backup
  and restore refuse them.
- Audit trail now redacts session ids, cookies, credentials, API keys and licence keys as well as
  passwords, salts and signatures.
- Electron: sandbox + context isolation on every window, no webviews, no remote content, IPC
  calls rejected unless they come from the app’s own renderer.

## Installation (new shop)

1. Run `Sauda-Retail-Suite-Setup-1.1.4.exe` on the **Main PC** (Windows 10/11 x64).
2. Complete Setup (business details, admin user).
3. Activate the shop licence: Settings → Licence (use the file issued by
   `Sauda-License-Generator-1.1.4.exe`).
4. To use Client PCs: Settings → Network → turn Server Mode on. Allow the Windows firewall prompt
   for **Private** networks only. Never allow it for Public networks.
5. On each Client PC: install the same setup file, choose **Client PC**, enter the Main PC’s
   address / scan the pairing QR, then approve the pending device on the Main PC
   (Settings → Devices).
6. Sell on the Main PC first and confirm a receipt prints before pairing the second PC.

## Upgrading from v1.1.3

1. **Back up first** on the Main PC: Shop → Backup, then copy the file off the machine. Note the
   counts (products / sales / customers / total dues) — you will compare them after the upgrade.
2. Close the app on every PC.
3. Install `Sauda-Retail-Suite-Setup-1.1.4.exe` on the Main PC and start it. The existing database
   is opened and upgraded in place; the upgrade is **strictly additive** (new tables only, no
   table or column is altered or deleted, no row is rewritten) and a pre-upgrade copy is written
   automatically.
4. Confirm the counts from step 1 match, then open a sale, a purchase and a report.
5. On each Client PC: install 1.1.4 and **re-pair**. Client PCs on v1.1.3 cannot talk to a v1.1.4
   Main PC (the old shared-token channel has been removed on purpose).
6. Keep the v1.1.3 installer and the backup until you are satisfied.

## Backup

- Main PC: Shop → Backup (manual) and Settings → Backup schedule (automatic). Backups are written
  under `%APPDATA%\Sauda Retail Suite\backups`.
- A Client PC never holds the shop’s database and refuses backup/restore by design.
- Copy a backup off the Main PC regularly — a backup on the same disk does not survive a disk
  failure.

## Rollback (v1.1.4 → v1.1.3)

1. Quit the app on all PCs (tray → Quit) so the database lock is released.
2. Uninstall v1.1.4 (data directory is preserved).
3. Reinstall the v1.1.3 installer.
4. Replace `%APPDATA%\Sauda Retail Suite\data\sauda.db` with the pre-upgrade backup taken before
   the upgrade, and delete the `-wal` / `-shm` sidecars left by the v1.1.4 file.
5. Reinstall v1.1.3 on each Client PC.

There is **no automatic downgrade**: v1.1.3 cannot open a v1.1.4 database, which is why the backup
is mandatory rather than optional.

## Known limitations

- Client PCs require a working network to the Main PC; there is no offline trading mode by design.
- A v1.1.3 Client PC must be upgraded and re-paired.
- The Main Server keeps running in the tray after the window is closed (by design, configurable);
  quitting explicitly stops it.
- Licence-signing key rotation is a manual, documented procedure.
- Maximum device count is whatever the licence states; no throughput figures are published
  because none were measured on customer hardware.
- If Windows shows “Unknown publisher”, the build was not signed — see the signature block above.
