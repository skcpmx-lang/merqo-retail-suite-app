# টেস্টিং ও যাচাই

এই ডকুমেন্টে সৎভাবে লেখা আছে **কী যাচাই হয়েছে** এবং **কী এখনো বাস্তব উইন্ডোজ মেশিনে যাচাই করা হয়নি**।

## ১. স্বয়ংক্রিয় যাচাই (এখনই চলে)

```bash
npm run verify
```

এটি ক্রমান্বয়ে চালায়:

1. `tsc -p packages/core` — টাইপচেক
2. `tsc -p packages/app` — Electron main + ১৭টি রেন্ডারার পেজ
3. `tsc -p packages/license-generator`
4. `vitest run` — **৫৩টি টেস্ট**
5. `scripts/make-icons.mjs` — আইকন
6. `esbuild` + `vite` — দুই অ্যাপের আসল বিল্ড
7. সিক্রেট স্ক্যান — `git ls-files`-এ কোনো কী/`.pem`/`secrets/` নেই কিনা

শেষ সফল রান (এই রিপোজিটরির বর্তমান অবস্থা):

## ২. টেস্ট কভারেজ (কী কী আছে)

`packages/core/test/workflow.test.ts` — বাস্তব ব্যবসার প্রবাহ:

- সেটআপ → অ্যাডমিন তৈরি → ওয়াক-ইন কাস্টমার
- প্রোডাক্ট তৈরি (ওপেনিং স্টক, ইউনিট ফ্যাক্টর)
- পারচেজ → স্টক বাড়া → **ওয়েটেড অ্যাভারেজ কস্ট** যাচাই
- বিক্রয় (নগদ) → স্টক কমানো → প্রফিট (COGS সহ)
- বাকি বিক্রয় → কাস্টমার ব্যালেন্স → আদায় → ব্যালেন্স শূন্য
- রিটার্ন (restock) → স্টক ও ব্যালেন্স সমন্বয়
- void বিক্রয় → স্টক/পেমেন্ট ফেরত, ডকুমেন্ট অক্ষত
- ক্যাশ সেশন খোলা/বন্ধ, প্রত্যাশিত বনাম গণনা
- এক্সপেন্স ও void
- রিপোর্টের মোট = লেজারের মোট (ক্রস-চেক)

`packages/core/test/extras.test.ts` — POS-এর দৈনন্দিন দেখার জিনিস:

- অফার-সহ কার্যকর বিক্রয়মূল্য (`final_price_paisa`, `offer_active`) ও শূন্যের নিচে না নামা
- প্রাইস লেবেল: প্রাইমারি বারকোড → SKU ফলব্যাক, `SAUDA:<id>` QR পেলোড, ইউনিট
- গ্লোবাল সার্চ: বাংলা নাম, SKU, বারকোড, কাস্টমারের ফোন; প্রতি ধরনে লিমিট

`packages/core/test/core.test.ts` — নীতি ও প্রান্তিক কেস:

- Money: `roundDiv` half-up, poisa ↔ taka, বাংলা অঙ্ক
- qty milli ↔ base milli (কেজি → গ্রাম)
- ডিসকাউন্ট (percent/fixed) ও VAT পদ্ধতি
- ফিঙ্গারপ্রিন্ট weighing, placeholder প্রত্যাখ্যান, থ্রেশহোল্ড
- লাইসেন্স issue → verify round-trip; পেলোড বদলে signature ব্যর্থ; মেয়াদোত্তীর্ণ; ডিভাইস মিসম্যাচ
- ব্যাকআপ তৈরি → যাচাই → রিস্টোর; নষ্ট ফাইল প্রত্যাখ্যান
- CSV ইমপোর্ট প্রিভিউ/কমিট (সঠিক ও ভুল সারি)
- UTF-8/বাংলা সার্চ ফোল্ডিং ও সর্ট

## ৩. ম্যানুয়াল যাচাই যা ডেভেলপারকে করতে হবে

| আইটেম | কেন স্বয়ংক্রিয় নয় |
|---|---|
| NSIS ইনস্টলের পর অ্যাপ চালু হওয়া | Electron রানটাইম প্রয়োজন (এই স্যান্ডবক্সে নেই) |
| ৫৮/৮০ মিমি থার্মাল রিসিটের ফিজিক্যাল আউটপুট | আসল প্রিন্টার দরকার |
| সাইলেন্ট প্রিন্টের কাগজের উচ্চতা | ড্রাইভার-নির্ভর |
| রিস্টোরের পর অ্যাপ পুনরায় চালু | ফাইল লক/প্রসেস রিস্টার্ট |
| দুই কম্পিউটারে লাইসেন্স মিসম্যাচ | আসল হার্ডওয়্যার দরকার |
| বাংলা ফন্টে রেন্ডারিং (Nirmala UI) | Windows ফন্ট |
| হাই-ডিপিআই ও একাধিক মনিটর | ফিজিক্যাল স্ক্রিন |

**নীতি:** যাচাই না হওয়া পর্যন্ত কোনো ইনস্টলার বা প্রিন্টিং “কাজ করছে” বলে দাবি করা হয় না।
Windows CI বিল্ড আর্টিফ্যাক্ট আসল প্রমাণ; `docs/09-known-limits.md`-এ অবস্থা লেখা থাকে।

## ৪. রিগ্রেশন প্রতিরোধ

- সব আর্থিক হিসাব এক ফাংশন (`computeSale`, `computePurchase`) দিয়ে — UI-তে আলাদা সূত্র নেই।
- রেন্ডারারে কোনো `* 100` / `/ 100` টাকার গুণভাগ নেই; শুধু `money()` ফরম্যাটার।
- `void` টেস্ট নিশ্চিত করে ডকুমেন্ট মুছে না গিয়ে অবস্থা বদলায়।
- প্রতিটি IPC রুটে অনুমতি — নতুন রুট যোগ করলে `perm` না দিলে টাইপ এরর (Route ইন্টারফেস)।
- সিক্রেট স্ক্যান CI-তে বাধ্যতামূলক।

## ৫. নতুন টেস্ট লেখার নিয়ম

```ts
import { createTestDb, /* helpers */ } from './helpers.js';

const { db } = createTestDb();
// অ্যারেঞ্জ → অ্যাক্ট → অ্যাসার্ট
```

- প্রতিটি নতুন সার্ভিস ফাংশনের জন্য অন্তত একটি হ্যাপি পাথ ও একটি ব্যর্থ পাথ।
- টাকার অ্যাসার্শনে সরাসরি poisa সংখ্যা লিখুন (`expect(sale.total_paisa).toBe(130000)`), ফরম্যাট করা স্ট্রিং নয়।
