## 2. Architecture

```
Electron main process  ─────────────┐
  ├─ BrowserWindow (POS UI)         │  window close → hide to tray
  ├─ Tray (status + stop/restart)   │
  └─ server.ts (process singleton) ─┴─► ServerRuntime  (electron-free)
                                          ├─ start / stop / restart state machine
                                          ├─ lock file  <data>/server.lock
                                          ├─ HTTP listener (core/net/rpc)
                                          ├─ health snapshot (port, clients, DB, last backup)
                                          └─ crash supervisor (backoff, capped)
```

`packages/app/electron/server-runtime.ts` deliberately imports **nothing from Electron**. Its tests
run without a display, and the UI cannot keep the server alive by accident.

### Files

| File | Role |
|---|---|
| `packages/app/electron/server-runtime.ts` | **new** — runtime, lock, health, supervisor, pure lifecycle decisions |
| `packages/app/electron/server.ts` | **new** — process-wide singleton handle shared with the IPC layer |
| `packages/app/electron/main.ts` | tray, window-close policy, auto-start, graceful quit, crash reporting |
| `packages/app/electron/ipc.ts` | `server.*` routes; `lan.*` host routes now delegate to the runtime |
| `packages/app/electron/lan.ts` | host lifecycle removed — terminal client + probe only (one owner) |
| `packages/app/src/pages/Settings.tsx` | live server panel, keep-running and auto-start switches |
| `packages/core/src/domain/types.ts`, `db/seed.ts` | settings `server_autostart`, `server_keep_running` |

## 3. Behaviour implemented

1. **Window close does not stop the server.** With the server running and “keep running” on, the
   POS window hides to the tray (`decideWindowCloseAction`). Quitting is explicit.
2. **Server survives the last window.** `window-all-closed` returns without quitting while the
   server is up.
3. **Graceful quit.** `before-quit` stops the listener first, then checkpoints and closes SQLite, then
   quits — no request can arrive while the database closes.
4. **Auto-start.** On launch, a host-role install with `server_autostart = 1` starts the server by
   itself; a failure (busy port, missing token, other process) is logged and surfaced, never hidden.
5. **Windows auto-start.** `app.setLoginItemSettings({ openAtLogin })` follows the same setting.
6. **Tray.** Live status line, client count, database state, open window, restart, stop (with a
   confirmation naming the connected-client count), quit.
7. **Duplicate prevention.** In-process registry + lock file with PID/instance. A second runtime for
   the same store is refused; a stale lock from a dead PID is reclaimed.
8. **Crash recovery.** `reportCrash()` from the process-level handlers restarts with exponential
   backoff (1s → 30s, max 5 attempts) and then stops trying, leaving an explicit error state.
9. **Health.** State, port, addresses, clients, uptime, restarts, last error/code, DB integrity,
   last backup, lock ownership — exposed to the tray and to `server.status`.
10. **IPC surface.** `server.status`, `server.start`, `server.stop`, `server.restart`,
    `server.setAutostart`, `server.setKeepRunning` (all `settings.manage`, audited writes).

## 4. Automated evidence

`packages/app/test/server-runtime.test.ts` — **14 tests**, real HTTP on loopback, real SQLite, real
lock file, no mocks:

| Test | Proves |
|---|---|
| starts a real listener and stops it cleanly | port opens; after stop the port refuses connections |
| advertises a full health snapshot | state/clients/db_ok/lock_held/addresses are real |
| refuses a start without a shop token | `TOKEN_MISSING`, state `error`, no listener |
| hides to the tray while the server runs | window-close decision + the listener still answers afterwards |
| allows a real quit / closes when no server | quit and no-server paths unchanged |
| keeps serving clients across a window-close cycle | three consecutive health calls after the window is gone |
| refuses a second runtime for the same store | `ServerBusyError`; first server still serving |
| reports a busy port | second server gets `EADDRINUSE`; first unaffected |
| restarts without corrupting the database | `quick_check = ok`, row still present, new listener answers |
| restarts itself after a crash report | state goes `error → running`, `restarts ≥ 1` |
| gives up after the retry budget | `auto_restart = false` leaves an explicit error |
| can be stopped twice | idempotent stop |
| auto-start decision matrix | only host + opt-in |
| tray tooltip descriptions | all five states render |

Full suite: **314 tests / 27 files** (was 300/26). `npm run verify` green (typecheck ×3, tests,
UI wiring 249 routes / 188 call sites, both builds, secret scan, trust-boundary gate, dependency audit).

**A regression the tests caught during development:** `stop()` returned early for an `error` state and
leaked the listener, so a crash-restart failed with `EADDRINUSE`. Fixed, and the crash test now guards it.

## 5. What this changes for existing installations

- Two new settings with safe defaults: `server_keep_running = 1`, `server_autostart = 0`.
  An upgraded v1.1.3 shop therefore keeps its current behaviour (no server at launch) until the
  operator enables auto-start — no surprise listener after an upgrade.
- No schema change in this phase; business tables, sales, journals and licences are untouched.
- `lan.startHost` / `lan.stopHost` still exist for the existing UI and now go through the same runtime,
  so there is exactly one owner of the listener.

## 6. NOT verified in this environment (honest list)

| Item | Why not | Manual check (Windows) |
|---|---|---|
| Tray icon and menu render, double-click restores | no Electron runtime here | install, close window, see tray icon, right-click menu |
| Window-close → tray on Windows | `close` handler is static-only here | close the window; process must stay in Task Manager; clients must keep selling |
| `setLoginItemSettings` (Windows startup) | needs a real Windows profile | enable auto-start, reboot, Task Manager → Startup tab shows the app, server listens |
| Graceful stop under load | no second PC | with a client mid-sale, stop the server → client shows a clear failure, no half-committed invoice |
| Tray stop confirmation dialog | native dialog | with ≥1 client connected, tray → stop → confirmation appears |
| Crash supervisor under a real renderer crash | cannot crash Electron here | kill the renderer via Task Manager → server keeps serving, log shows the restart |

Procedure details: `docs/V1.1.4_TEST_PLAN.md` §2.
