## What’s new

**Server / Client model.** One shop database on one Main PC; Client PCs work over the shop’s own
encrypted link. No shared folder, no database over SMB, no second copy of the books.

- Main PC / Client PC roles, chosen at setup.
- Client PCs hold no business data and cannot answer shop queries from their own file.
- **Device pairing with administrator approval:** a new PC stays *pending* and can do nothing until
  an admin approves it. Pairing codes are single-use and expire.
- **TLS with certificate pinning:** a Client refuses any server whose certificate does not match the
  pin it was paired with.
- **Device identities (Ed25519) and device-bound sessions**; revocation closes the live connection
  and ends the session immediately.
- **Replay protection that survives a restart.**
- **Honest offline behaviour:** no Main PC, no sale — nothing is queued to commit later behind the
  cashier’s back.
- **Live updates** between PCs through normal permission-checked reads; a missed or duplicated
  event can only delay a refresh, never inject data.

**POS stale-price and stale-stock protection.** If a price or stock level changes while an item is
in an unsent cart, the line is marked `• যাচাই করুন` and the cashier reviews the change. Committing
that cart is refused by the Main PC with a conflict naming the affected lines: the price is never
silently swapped, the cart is never emptied, nothing is sold. Two tills cannot sell the same last
unit, and a refused sale leaves no sale row, no payment, no stock movement and no consumed invoice
number.

**Hardening.** Single database boundary with role-stamped client files (backup/restore refuse them);
audit redaction extended to session ids, cookies, credentials, API/licence keys; Electron windows
sandboxed with context isolation, no webviews or remote content, IPC accepted only from the app’s
own renderer.

## Installation (new shop)

1. Run `Sauda-Retail-Suite-Setup-1.1.4.exe` on the **Main PC**.
2. Complete Setup (business details, admin user).
3. Activate the shop licence (Settings → Licence) using the file issued by
   `Sauda-License-Generator-1.1.4.exe`.
4. For Client PCs: Settings → Network → enable Server Mode, and allow the Windows firewall prompt
   for **Private** networks only.
5. On each Client PC: install the same file, choose **Client PC**, enter the Main PC’s address or
   scan the pairing QR, then approve the pending device on the Main PC (Settings → Devices).
6. Sell on the Main PC and confirm a receipt prints before pairing a second PC.

## Upgrading from v1.1.3

1. **Back up first** on the Main PC (Shop → Backup) and copy the file off the machine. Note the
   counts: products / sales / customers / total dues.
2. Close the app on every PC.
3. Install v1.1.4 on the Main PC and start it. The existing database is upgraded in place — new
   tables only, nothing altered or deleted, no row rewritten — and a pre-upgrade copy is written
   automatically.
4. Confirm the counts match, then open a sale, a purchase and a report.
5. On each Client PC: install v1.1.4 and **re-pair** (v1.1.3 clients cannot talk to a v1.1.4 Main
   PC; the old shared-token channel was removed deliberately).
6. Keep the v1.1.3 installer and the backup until you are satisfied.

## Backup

- Main PC: Shop → Backup (manual) and Settings → Backup schedule (automatic), written under
  `%APPDATA%\Sauda Retail Suite\backups`.
- A Client PC refuses backup/restore by design.
- Copy backups off the Main PC regularly — same-disk backups do not survive a disk failure.

## Rollback (v1.1.4 → v1.1.3)

1. Quit the app on all PCs (tray → Quit) to release the database lock.
2. Uninstall v1.1.4 (the data directory is preserved).
3. Reinstall v1.1.3.
4. Replace `%APPDATA%\Sauda Retail Suite\data\sauda.db` with the pre-upgrade backup and delete the
   `-wal` / `-shm` sidecars left by v1.1.4.
5. Reinstall v1.1.3 on each Client PC.

There is no automatic downgrade: v1.1.3 cannot open a v1.1.4 database, which is why the backup is
mandatory.

certutil -hashfile Sauda-License-Generator-1.1.4.exe SHA256
powershell -NoProfile -Command "Get-AuthenticodeSignature 'Sauda-Retail-Suite-Setup-1.1.4.exe' | Format-List Status,SignerCertificate"

Compare the hashes with `SHA256SUMS.txt` from this release page and check that `Status` is `Valid`
before running the installer.

## Known limitations

- Client PCs require a working network link to the Main PC; there is no offline trading mode by
  design.
- v1.1.3 Client PCs must be upgraded and re-paired.
- The Main Server keeps running in the tray after the window closes (configurable); quitting stops
  it explicitly.
- Licence-signing key rotation is a manual, documented procedure.
- Device count is bounded by the licence; no throughput figures are published because none were
  measured on customer hardware.
- If Windows shows “Unknown publisher”, the build was not signed — check the signature block above
  and do not install a file whose hash does not match `SHA256SUMS.txt`.
