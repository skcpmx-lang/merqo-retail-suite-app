# V1.1.5 — Windows virtual-machine and two-PC test plan

**Status of this gate: BLOCKED / NOT EXECUTED.**

There is no Windows 10 or 11 desktop VM in the environment this release was prepared in — only Linux
containers and GitHub's headless `windows-latest` runner, which has no interactive desktop, no second
PC, no printer and no scanner. The automated Windows gate (build, tests, packaging, installer checks)
does run and is reported honestly in `V1.1.5_TEST_REPORT.md`. The checks below require a human at a
real desktop and **must not be reported as passed until they are actually run.**

Everything here is written so the owner can execute it and record the result: no step depends on
knowledge that is only in someone's head, and each row produces evidence (a screenshot, a file, a log
line) rather than an opinion.

## 0. What you need

| Item | Detail |
| --- | --- |
| Host | A machine with Hyper-V, VMware or VirtualBox and ~40 GB free |
| VM A "Main PC" | Windows 10 22H2 **or** Windows 11 23H2, 4 GB RAM, 2 vCPU, 60 GB disk, **unsigned installers allowed** |
| VM B "Counter PC" | Same image, on the **same virtual network** (NAT with a shared subnet, or an internal switch) |
| Installers | `Sauda-Retail-Suite-Setup-1.1.5.exe`, `Sauda-License-Generator-1.1.5.exe`, `SHA256SUMS.txt` |
| Licence | One Main-PC licence and one Client-PC licence, issued from the License Generator |
| Printer | Optional but recommended: any printer driver that can render to PDF, for receipt layout |
| Time | ~3 hours for the full list, ~45 minutes for the smoke subset (T01, T02, T05, T10, T20, T30) |

Snapshot the VM before each group so a failure can be re-run from a known state.

## 6. Recording results

For each ID record: **PASS**, **FAIL (with what happened)** or **NOT RUN**. A failure produces a short
report with the screenshot, the log tail from `%APPDATA%\Sauda Retail Suite\logs`, and the step
number — that is what makes a follow-up fix possible without reproducing the whole session.

Do not mark a row PASS on the basis of "it worked on my other machine"; the point of the VM is that
the shipped installer, the shipped runtime and a clean Windows profile are what get tested.
