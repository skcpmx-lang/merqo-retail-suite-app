### Test environment note

`packages/app/test/ui-keyboard-v115.test.tsx` runs in jsdom (declared per file with
`// @vitest-environment jsdom`), because focus and keyboard behaviour cannot be asserted against a
string of HTML. `@testing-library/react`, `@testing-library/dom` and `jsdom` are development
dependencies only; nothing new ships in either installer.

## 3. Negative and edge-case tests added in v1.1.5

Each one is written against the **old** behaviour and fails if the fix is reverted (verified by
reverting the fix locally and re-running):

| Test | What it refuses |
| --- | --- |
| `sse-shutdown-v115` | a stream registering after shutdown; a header written to a dying socket; a timer surviving `stop()`; `closeAll()` poisoning the hub |
| `inventory-atomicity-v115` | stock moved while the ledger posting failed (missing ledger account) |
| `sale-price-floor-v115` | a legal sub-unit sale being refused, and an illegal one being allowed, with the floor converted into the sold unit |
| `cash-atomicity-v115` | a drawer movement surviving a failed posting (cash counted, ledger silent); a journal entry surviving with only some of its lines |
| `effect-deps-v115` | a loader running twice per render, a filter change not reloading, a shop default customer ignored because settings arrived after the screen mounted |
| `giftcard-atomicity-v115` | a gift card whose balance moved while its transaction history (and the reason for the change) did not |
| `sale-serials-v115` | a serial sold for the wrong product; two products sharing a serial string losing stock together; the wrong cart line being checked |
| `restore-safety-v115` | truncated backups, non-SQLite files, a client database restored over a shop; two backups in one second overwriting each other; a restore whose swap failed leaving no database |
| `ui-keyboard-v115` | focus escaping a dialog, focus lost on close, a mouse-only row, tabs without arrow keys, an unannounced selection |

## 4. What a green suite does **not** prove

Stated plainly, because this is where releases usually over-claim:

1. **No interactive Windows desktop has run the app.** Electron window management, DPI scaling,
   Bengali font fallback and tray behaviour are unverified on the shipped platform.
2. **No two-PC LAN test** on real hardware: pairing, approval, revocation propagation under load and
   sleep/wake recovery are covered by tests against loopback sockets only.
3. **No printer, scanner or cash drawer** was exercised.
4. **No real v1.1.4 shop database** was upgraded; migrations are tested against synthetic databases
   built by the test helpers.
5. **No antivirus interference** was simulated (the Windows agent behaviour behind A-14's rename).

## 6. Installer gate

`release.yml` builds both NSIS installers on `windows-latest`, verifies version metadata, x64
architecture, the absence of key material and the SHA-256 sums, re-downloads the uploaded assets and
verifies them again, and only then publishes. It runs on a `v*` tag; the version and asset names are
derived from `packages/app/package.json` (v1.1.5), and a tag that disagrees with the manifest fails
before anything is built.

The VM-level checks that cannot run in this environment are listed in `V1.1.5_VM_TEST_PLAN.md`, are
**not** reported as passed, and stay the owner's gate.
