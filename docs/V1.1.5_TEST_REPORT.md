## 4. What a green suite does **not** prove

Stated plainly, because this is where releases usually over-claim:

1. **No interactive Windows desktop has run the app.** Electron window management, DPI scaling,
   Bengali font fallback and tray behaviour are unverified on the shipped platform.
2. **No two-PC LAN test** on real hardware: pairing, approval, revocation propagation under load and
   sleep/wake recovery are covered by tests against loopback sockets only.
3. **No printer, scanner or cash drawer** was exercised.
4. **No real v1.1.4 shop database** was upgraded; migrations are tested against synthetic databases
   built by the test helpers.
5. **No antivirus interference** was simulated (the Windows agent behaviour behind A-14's rename).

## 6. Installer gate

`release.yml` builds both NSIS installers on `windows-latest`, verifies version metadata, x64
architecture, the absence of key material and the SHA-256 sums, re-downloads the uploaded assets and
verifies them again, and only then publishes. It runs on a `v*` tag; the version and asset names are
derived from `packages/app/package.json` (v1.1.5), and a tag that disagrees with the manifest fails
before anything is built.

The VM-level checks that cannot run in this environment are listed in `V1.1.5_VM_TEST_PLAN.md`, are
**not** reported as passed, and stay the owner's gate.
