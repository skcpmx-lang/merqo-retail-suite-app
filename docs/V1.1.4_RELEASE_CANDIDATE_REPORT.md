### Why the installers are missing

This environment has no Windows host and `npm ci` was run with
`ELECTRON_SKIP_BINARY_DOWNLOAD=1`, so there is no Electron binary. Packaging was genuinely
attempted, and it failed for a structural reason, not a missing flag:

```
$ npm run dist:app
  • electron-builder  version=26.18.0 os=6.1.158+
  • executing @electron/rebuild  electronVersion=43.8.7 arch=x64 buildFromSource=false
  • preparing       moduleName=better-sqlite3 arch=x64
  ⨯ node-gyp does not support cross-compiling native modules from source.
[package-app] electron-builder failed.
```

`better-sqlite3` is a native module. A Windows x64 build of it can only be produced by a
**Windows x64 toolchain** (or a prebuilt binary for that ABI). Cross-compiling from Linux is
refused by `@electron/rebuild`. There is also no code-signing certificate in this environment,
so any installer produced here would be unsigned and useless for real distribution.

## 2. Exact procedure to produce the RC (Windows host)

Run on a **Windows 10/11 x64** machine with Node 22, Visual Studio Build Tools (C++ workload) and
Python 3 available to `node-gyp`:

```bat
git checkout arena/597b03e9-merqo-retail-suite-app
git rev-parse HEAD                                  :: must be 3357f12... (or the approved merge commit)
npm ci
npm run typecheck
node node_modules\vitest\vitest.mjs run             :: expect 545 passed / 51 files
npm run verify
npm run dist:app                                    :: -> packages\app\release\Sauda-Retail-Suite-Setup-1.1.4.exe
npm run dist:license-generator                      :: -> packages\license-generator\release\Sauda-License-Generator-1.1.4.exe
```

Then, in the directory holding both `.exe` files:

```bat
certutil -hashfile Sauda-Retail-Suite-Setup-1.1.4.exe SHA256
certutil -hashfile Sauda-License-Generator-1.1.4.exe SHA256
```

Paste those two real digests into `SHA256SUMS.txt` (GNU format, lowercase hex, two spaces, file
name) and record the file sizes. Only then does this report's §1 table become complete.

If the build is signed, the certificate must be an EV/OV code-signing certificate held outside the
repository; `CSC_LINK`/`CSC_KEY_PASSWORD` may be supplied by the build machine's environment and
must never be committed or written into `packages/*`.

## 5. Upgrade notes (v1.1.3 → v1.1.4)

1. **Back up first.** On the Main PC: Shop → Backup → create, and copy the produced file off the
   machine. The upgrader runs `migrate()` which itself writes a pre-migration copy, but the
   operator's own backup is the rollback anchor.
2. **Schema v5 + v6 are strictly additive.** Two new tables for the multi-PC foundation and two for
   restart-safe replay protection. No `ALTER`, no `UPDATE`, no `DELETE` on existing rows, so a
   v1.1.3 shop keeps every product, sale, journal line, user and setting.
3. **Single-PC shops are unaffected.** Server Mode stays off by default; POS, purchasing, stock,
   accounting and reports behave as in v1.1.3. Nothing is sent over the network until an
   administrator turns Server Mode on and pairs a device.
4. **Licence:** a v1.1.3 licence file still activates. A v2 licence (store-bound) is required for
   multi-PC; it is minted by the v1.1.4 license generator for the Main PC's fingerprint.
5. **Client PCs** need a fresh pairing (QR/pairing code + admin approval). The v1.1.3 shared-token
   `/rpc` tunnel is gone; a v1.1.3 client build cannot talk to a v1.1.4 Main PC, and must be
   upgraded and re-paired.
6. **Firewall:** the Main PC opens the v1.1.4 HTTPS port on the LAN only. Windows Defender
   Firewall may prompt once; allow it for *Private* networks only, never for Public.
7. **Keep-running:** the Main Server keeps running in the tray after the window closes when
   `server_keep_running` is on. Quitting explicitly stops the listener and closes the database.
8. **Client PCs must not be pointed at a file share.** The database is never shared over SMB.

## 6. Rollback

1. Stop the app on every PC (tray → Quit) to release the database lock.
2. On the Main PC, uninstall v1.1.4 (settings and the data directory are preserved by the
   uninstaller).
3. Reinstall the v1.1.3 installer.
4. Replace `%APPDATA%\Sauda Retail Suite\data\sauda.db` with the pre-upgrade backup taken in step 1
   of §5, and remove the `-wal`/`-shm` sidecars that belong to the v1.1.4 file.
5. Reinstall v1.1.3 on each client PC and forget the paired server.

There is **no automatic schema downgrade**: v1.1.3 would refuse a v6 file, which is why the backup
is mandatory rather than optional. Restoring only the database without the matching v1.1.3 binary
is not a rollback.

## 8. Known limitations carried into the RC

- Installers are unsigned until a Windows signing step is added; SmartScreen will warn.
- Licence signing key rotation is manual (documented, not automated).
- The multi-PC capacity limit is whatever the licence states; measured throughput numbers are not
  claimed because they were not measured on real hardware.
- Windows-specific behaviour (DPAPI, firewall, printing, drawer, scanner, display, sleep/wake,
  long-lived streams) remains **NOT VERIFIED** in this environment.
