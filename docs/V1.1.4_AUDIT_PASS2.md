## 2. Licence lifecycle (Main App + Generator)

### Fixed

| # | Defect | Where | Test |
| --- | --- | --- | --- |
| 1 | A **revoked** licence could be exported again (`toLicenseFile` serialised any record). The `.sauda` file still activates offline, so re-exporting silently undid the operator's revocation. | `packages/license-generator/src/domain.ts` | `recovery-v114` |
| 2 | A **corrupt store file** surfaced as a raw `SyntaxError`, with no recovery guidance — and the generator would keep working from memory. It now fails closed with a Bangla message naming the file and telling the operator not to delete it. Two more shapes (`[]`, malformed object) are refused instead of being coerced. | `packages/license-generator/src/domain.ts` | `recovery-v114` |

### Verified (executed)

- **Revocation**: reason required, double revocation refused, ledger marks the licence revoked, the
  file still verifies as *revoked* when the id is known, re-export refused.
- **Renewal**: a re-issue supersedes the previous record (`superseded_by`), the new file verifies,
  the old one stays revoked; the Main App replaces the activation row.
- **Expiry**: an expired licence verifies as `expired` and cannot activate; the generator refuses to
  mint a past-dated licence; `licenseState` reports `expired` once the date passes.
- **Device replacement**: a licence bound to other hardware stops verifying; a re-issued licence for
  the same PC identity works.
- **Device reactivation**: a revoked device cannot re-enrol, cannot be re-approved, and its session
  dies immediately; an approved device re-enrolling does not consume a second slot; a rejected
  device cannot open a session.
- **Store migration**: a licence naming another store is refused at activation (`store_mismatch`,
  audited, nothing stored); licences without a store binding keep working (legacy path).
- **Application reinstall**: an empty database activates the same licence and gets capacity back.
- **Backup/recovery**: `createBackup` → restore into a fresh database keeps activation, capacity and
  device approvals; corrupted/tampered stored activation payload or signature ⇒ `schema_invalid` /
  `signature_invalid`, no access, and no capacity.
- **Restart persistence**: activation, capacity and device status survive a real database reopen;
  a revoked session stays revoked after restart.
- **Device limit**: pending requests count against the licence, approvals cannot exceed it, and the
  capacity figure always comes from a verified source (activation payload or a registered
  SERVER_POS row), clamped to 100.
- **Legacy compatibility**: v1 licences (no `store_id`/`device_id`) activate and verify unchanged.
- **Cache/offline**: the only cache is the 60-second licence gate in `ipc.ts` (kept: the hardware
  probe is expensive); expiry and clock tamper are re-evaluated after it, and every stored-state
  read re-verifies the signature.

## 3. Client SSE lifecycle

### Fixed

| # | Defect | Where | Test |
| --- | --- | --- | --- |
| 3 | A stream closed by the server for **`revoked` / `device-not-approved` / `session-expired`** was retried by the client anyway (the `end` handler re-armed a reconnect), producing a stream of rejected connections. These reasons are now terminal: the client closes and reports `retryable: false`. | `packages/core/src/net/sse-client.ts` | `sse-reconnect-v114` |
| 4 | **No backoff**: every reconnect used the same fixed delay, so a dead Main PC was hammered. Delays now grow with each attempt, are capped (`backoffMaxMs`, default 10 s) and jittered ±15 %. | same | `sse-reconnect-v114` |
| 5 | **No idle watchdog**: a half-open connection (sleep/wake, Wi-Fi change, cable pull) stayed "connected" indefinitely because nothing arrives and TCP does not fail fast. A silent connection is now detected after `idleTimeoutMs` (default 45 s, server pings every 15 s), destroyed and retried. | same | `sse-reconnect-v114` |
| 6 | **Unbounded line buffer**: a peer that never sends a newline could grow memory without limit. Now capped (`maxBufferBytes`, 1 MiB) → `STREAM_OVERFLOW` + reconnect. | same | `sse-reconnect-v114` |
| 7 | When the Main PC ended a **client session** (`SESSION_EXPIRED`, `SESSION_REVOKED`, `DEVICE_REVOKED`), the client kept its user and its stream, so the UI stayed "signed in" while every action failed. The client now drops the session and stream; a fresh login reopens the stream. The server remains the authority. | `packages/app/electron/v1-transport.ts`, `main.ts` | `session-loss-v114` |

### Verified (executed)

- Disconnect detection: `end`, `error`, terminal `closed` events, exhaustion, idle, overflow.
- Reconnection strategy: resume from the last id, `Last-Event-ID` re-sent on every attempt, retry
  limit reported as `STREAM_EXHAUSTED`.
- Sequence recovery: a jump is reported through `onGap(from, to)`; duplicates are dropped
  (`id <= lastEventId`); unknown/`resync` events become a full refetch in the renderer.
- Backlog/retention: resume older than the retention floor yields an explicit `resync`
  (`HISTORY_TRUNCATED`), never a silent hole (server suite, unchanged).
- Buffer limits: server `maxBufferedBytes` + slow-consumer close; client cap added above.
- Session expiry / device revocation during an active stream: server closes the stream within one
  poll (~1 s) and the client now stops; sessions are revoked immediately on the server side.
- Server restart: client resumes from its stored id and receives the events written while it was
  away (existing socket-level test).
- Resume point persistence: `terminal.json` stores `last_event_id` on every event, is reused on the
  next open, dropped on `forget()`.
- Events stay hints: refreshers are called with **no arguments**, the registry stores no payload,
  duplicate hints collapse, a failing screen cannot block others.

### Not verified here (needs a real Windows PC)

- Actual sleep/wake and Wi-Fi/Ethernet change behaviour (the watchdog is tested against a fake dead
  peer, not against a real Windows suspend).
- OS-level TCP keepalive timings and corporate firewalls/NAT idle timeouts.

## 5. Cross-application integration

`packages/license-generator/test/full-flow-v114.test.ts` runs the whole chain over real TLS:

1. Generator signs a licence for the Main PC's hardware, bound to the shop's store id, and exports
   it with `toLicenseFile` — and verifies its own output first.
2. Main App activates that exact text (`signature → schema → expiry → hardware → store`), and
   reports capacity 3.
3. Client PC claims a pairing code with its own Ed25519 key; the device is `pending`.
4. A pending device cannot log in or read anything.
5. The Main Server approves the device.
6. The client logs in and executes an authenticated `/api/v1` RPC.
7. Enforcement: wrong store → `STORE_MISMATCH`; a claim declaring `SERVER_POS` → `BAD_ROLE`
   (capacity unchanged); a replayed single-use pairing code → refused; capacity accounting stays
   correct.

Both applications share `@sauda/core` (payload schema, key encoding, canonical JSON, verification
order) — there is no second implementation to drift.

## 6. Remaining defects and limitations (not fixed in this pass)

| # | Item | Severity | Why it stays |
| --- | --- | --- | --- |
| 1 | **Offline revocation cannot reach an activated Main App.** The `.sauda` file is signed and local; there is no phone-home. Revoking in the generator stops re-export and marks the record, but an already-activated PC keeps working until the licence expires. | Medium (product limitation) | Fixing it needs an online revocation channel or short-lived licences — an architecture decision, not a bug fix. Mitigation shipped: re-export is blocked, re-issue supersedes, expiry is enforced. Documented in the release notes. |
| 2 | Device revocation closes an open SSE stream within one poll interval (~1 s), not instantly. | Low | Sessions and credentials are revoked immediately, so no new request succeeds; only already-queued events can still flow for that second. |
| 3 | The licence gate caches activation state for 60 s, so a licence that expires keeps working for up to a minute. | Low | Deliberate: `getActivationState` probes hardware. Expiry and clock tamper are still re-evaluated on the next check. |
| 4 | A licence's `device_id` / `device_role` are not enforced at activation. | Low | Binding is by hardware fingerprint + store id; enforcing a terminal id before the terminal exists would block activation. Documented. |
| 5 | Backlog replay uses the events retention window; a client offline longer than retention gets a full resync (correct, but a full refetch). | Low | By design; server announces `HISTORY_TRUNCATED`. |
