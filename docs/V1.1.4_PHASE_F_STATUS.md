## 4. What is blocked, and exactly what is needed

### 4.1 Windows production build (blocks §4.2, §5, §6 of the authorisation)

`npm run dist:app` was executed here and fails structurally:

```
⨯ node-gyp does not support cross-compiling native modules from source.
[package-app] electron-builder failed.
```

`better-sqlite3` is a native module; a Windows x64 binary must be produced on Windows x64.
There is no Windows host, no `wine`, no `nsis`, and no Visual Studio build tools here
(`signtool`, `osslsigncode`, `makensis`, `wine` all absent).

**Required:** a Windows 10/11 x64 machine (physical or VM, not WSL) with Node 22 LTS x64,
VS 2022 Build Tools with the “Desktop development with C++” workload + Windows 10/11 SDK,
Python 3.12, ≥ 5 GB free disk — or a CI runner with a `windows-latest` label. The exact command
sequence is §3.2 of `V1.1.4_RELEASE_CANDIDATE_REPORT.md`.

### 4.2 Authenticode signing (hard gate: no unsigned release)

Nothing can be signed here: no certificate, no PFX, no hardware token, no cloud-signing credential
in the environment, and no `signtool`.

**Required — one of these three, supplied to the build host only (never to the repo or chat):**

1. **PFX + password** (OV/EV certificate that permits software key storage):
   `CSC_LINK=<path or base64>`, `CSC_KEY_PASSWORD=<password>` in the build machine’s environment;
   electron-builder signs during `npm run dist:app`.
2. **Hardware token** (SafeNet eToken / YubiKey PIV — the CA/B-forum default since 2023):
   token plugged into the build host, PIN entered at build time; electron-builder is pointed at
   the certificate thumbprint (`--config.win.certificateSubjectName="<Subject>"`) and
   `signtool` prompts for the token PIN.
3. **Cloud signing** (Azure Trusted Signing / DigiCert Software Trust Manager):
   account endpoint, certificate profile name, and a federated/authorised credential on the build
   host.

**Certificate requirements:** publicly trusted CA, EKU “Code Signing” (`1.3.6.1.5.5.7.3.3`),
subject legal name matching the vendor entity that will appear to users, RSA ≥ 3072 or ECC P-256,
validity covering the release, and RFC-3161 timestamping
(`http://timestamp.digicert.com` or the CA’s equivalent).

**Never needed by the build:** the licence-signing key. That key belongs to the licence-issuing
step only; it must not exist on the build host and must never appear in the repository, the
installers, the chat or any log.
