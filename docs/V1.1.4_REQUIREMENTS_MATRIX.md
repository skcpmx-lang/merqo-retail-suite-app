## Change log of this matrix

- 2026-11-04 · Phase 0 — matrix created from the v1.1.3 baseline; no row was DONE for v1.1.4 work.
- 2026-11-04 · SSE wiring/hardening pass — `EventStreamHub` with a documented concurrent-stream policy
  (default 32), slow-consumer protection (1 MiB buffer), strict `Last-Event-ID` parsing (400
  `BAD_LAST_EVENT_ID`), `resync` when the resume point is below the retention floor, distinct
  `session-expired` / `device-not-approved` close reasons, one-stream-per-device replacement, and
  `pruneEventsByAge` retention that keeps a minimum number of events. 14 new tests; repo total
  **430 / 37 files**.
- 2026-11-04 · Phase 3 Milestone E — device administration: electron-free admin logic (approve,
  reject, revoke, capacity, identity, single-use pairing code), nine `devices.*` routes gated by
  `settings.manage`, and an admin panel in Settings → Network (6 tests; repo total **416 / 36 files**).
  Approval/revocation over `/api/v1` from a client PC, QR scanning and the Windows rendering are
  **not verified**.
- 2026-11-04 · Phase 3 Milestone D (partial) — `/api/v1` client (HTTPS-only, pinned, signed,
  idempotent), legacy shop-token tunnel bound to loopback by default with an explicit
  `SAUDA_ALLOW_LEGACY_RPC=lan` opt-in, and tests proving plaintext never reaches a protected
  operation. **Renderer migration and multi-PC terminal mode are NOT done** — see
  `docs/V1.1.4_PHASE3_MILESTONE_D.md` §2. Repo total **410 / 34 files**.
- 2026-11-04 · Phase 3 Milestone C — authenticated SSE (`GET /api/v1/events`) with device signature
  + device-bound session, revocable live streams, monotonic outbox sequence, `Last-Event-ID` resume,
  gap reporting and an HTTPS-only reconnecting client (12 tests; repo total **395 / 32 files**).
- 2026-11-04 · Phase 3 Priority 1 — schema v6 (replay nonces + rotation journal), durable
  `SqliteReplayGuard` (a nonce can no longer be replayed after a restart), device credential
  envelope with an Electron DPAPI sealer and fail-closed policy, and administrator-authorised
  certificate rotation with crash recovery. 25 new tests; repo total **383 / 31 files**. Windows
  DPAPI, real restarts/reboots and rotation on real hardware remain **not verified**.
- 2026-11-04 · Phase 3 Milestone B — `/api/v1` over mandatory TLS (`server/info`, `pairing/claim`,
  `devices/self`, `auth/login`, `rpc`), Ed25519 request signing with replay guard, certificate
  persistence/recovery/rotation, idempotent `rpc` (27 new tests; repo total **358 / 29 files**).
  Also fixed a Milestone A defect: zero-prefixed random serials produced a non-minimal DER INTEGER
  (~1 certificate in 256 was rejected by OpenSSL) — 2 regression tests added.
  Device-side key storage (DPAPI), SSE and the renderer migration are still open; two-PC and Windows
  behaviour remain **not verified**.
- 2026-11-04 · Phase 3 Milestone A — certificate generation (hand-written DER, no new
  dependency), TLS listener, pinned client and negative security tests (15). Device
  authentication, `/api/v1` and SSE are the next milestones.
- 2026-11-04 · Phase 2 — Main Server runtime (`server-runtime.ts`, tray/menu wiring, window-close
  policy, auto-start, lock, health, crash supervisor) implemented with 14 integration tests. Tray
  rendering, Windows login item and real crash recovery remain **unverified** (no Electron/Windows).
- 2026-11-04 · Phase 1/2 (partial) — schema v5 (nine tables), store identity, device enrolment,
  approval/rejection/revocation, licensed-capacity enforcement, device credentials, persisted
  sessions, pairing tokens, idempotency helper and the event outbox are implemented and covered by
  18 new tests (`packages/core/test/devices-v114.test.ts`). Server runtime, HTTP API, discovery/QR,
  client mode and the UI are **not** started; they are the next phases.
