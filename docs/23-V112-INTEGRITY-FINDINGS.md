## ২. বিস্তারিত ট্রেসেবিলিটি

### F-1 — বাতিল বিক্রয়ে ব্যয় করা পয়েন্ট ফেরত আসত না

- **কী পাওয়া গেল:** গ্রাহক ৫০০ পয়েন্ট খরচ করে ১,০০০ পয়েন্ট আয় করলে, ইনভয়েস বাতিলে ১,০০০ বাদ যেত
  কিন্তু ৫০০ ফেরত আসত না — নিট ক্ষতি ৫০০ পয়েন্ট।
- **আসল কারণ:** `packages/core/src/services/crm.ts` → `reverseLoyaltyForSale()` শুধু
  `type = 'earn'` সারি রিভার্স করত, `type = 'redeem'` উপেক্ষা করত।
- **পরিবর্তন:** একই ফাংশন এখন `SUM(points) WHERE ref_type='sale' AND ref_id=?` দিয়ে **নিট** হিসাব করে
  (earn − redeem) এবং সেই নিটটি উল্টে দেয়। রিডিম্পশন শুধু বাতিল হয়ে যায় না, ফেরতও আসে।
- **টেস্ট:** `packages/core/test/invariants.test.ts` → “restores stock, cash, gift-card value and
  redeemed loyalty points”; `packages/core/test/crm.test.ts`।
- **যাচাই:** AUTOMATED PASS (লেজার ও পয়েন্ট লেজার উভয়ই আগে-পরের অবস্থায় মেলে)।

### F-2 — বাতিলে গিফট কার্ডের জমা টাকা হারানো

- **কী পাওয়া গেল:** ২৪,০০০ টাকার গিফট কার্ডে বিক্রি → ইনভয়েস বাতিল → ব্যালেন্স ২৪,০০০ কমে যেত,
  কিন্তু কার্ডে ফেরত বসত না। টাকা বাস্তবে অদৃশ্য।
- **আসল কারণ:** `voidSale` স্টক, ক্যাশ, জার্নাল ও পয়েন্ট রিভার্স করত, কিন্তু গিফট কার্ড
  লায়েবিলিটি পোস্টিং রিভার্স করত না; `promotions.ts`-এ ফেরত দেওয়ার কোনো সার্ভিসই ছিল না।
- **পরিবর্তন:** নতুন `restoreGiftCardsForSale(db, { saleId, userId, note })`
  (`packages/core/src/services/promotions.ts`) — প্রতি কার্ডে জমা টাকা থেকে লালিত (রিডিম − রিফান্ড/বাতিল)
  নিট হিসাব করে ফেরত দেয়, `type='void'` লেনদেন লেখে, আর **`status='void'` করা (ভল্ট) কার্ড পুনরুজ্জীবিত করে না**
  (`UPDATE … WHERE status <> 'void'`)। `voidSale` (`sales.ts`) একই ট্রানজেকশনের ভেতরে এটি ডাকে এবং
  অডিট বিস্তারিত-এ `giftCardRestored`/`giftCards` লেখে।
- **টেস্ট:** `invariants.test.ts` → “restores stock, cash, gift-card value …” (কার্ড ২৪,০০০ ফেরত) এবং
  “a vaulted gift card is never resurrected by a void” (১২,০০০ হিমায়িত থাকে)।
- **যাচাই:** AUTOMATED PASS।

### F-3 — ফেরতে নিষ্পত্তিকৃত টাকা কম দেখানো

- **কী পাওয়া গেল:** ১০,০০০ টাকার ফেরতে ২,০০০ নগদ ফেরত দিলে রিপোর্ট/UI দেখাত ১০,০০০ “বাকিতে সমন্বয়”,
  অথচ আসলে ৮,০০০ সমন্বয় হয়েছে — ক্রেডিট নোট ও কাস্টমার স্টেটমেন্টে ভুল অঙ্ক।
- **আসল কারণ:** `returns.ts`-এ `appliedToDue = requested - refund` (অনুরোধ করা পরিমাণ), ফেরতের
  প্রকৃত `total` নয়।
- **পরিবর্তন:** বিক্রয় ও ক্রয় — দুই রিটার্নেই `appliedToDue = total - refund`; ডক কমেন্টও সংশোধিত।
- **টেস্ট:** `invariants.test.ts` → sale-return `appliedToDue = 8000`, purchase-return `appliedToDue = 35000`।
- **যাচাই:** AUTOMATED PASS।

### F-4 — সাপ্লায়ার ছাড়া বাকি ক্রয়

- **কী পাওয়া গেল:** সাপ্লায়ার নির্বাচন না করে বাকি ক্রয় সংরক্ষণ করা যেত। জার্নালে পাওনা বাড়ত,
  কিন্তু কোনো সাপ্লায়ার খাতে টাকা বসত না → মিলকরণ রিপোর্টে স্থায়ী পার্থক্য।
- **আসল কারণ:** `purchases.ts` `createPurchase()`-এ `due ≠ 0 && !supplierId` একেবারেই নিষিদ্ধ ছিল না।
- **পরিবর্তন:**
  1. সার্ভিস এখন স্পষ্ট বাংলা ত্রুটি দেয়: `বাকি থাকলে সাপ্লায়ার নির্বাচন করুন — নইলে পুরো টাকা পরিশোধ করতে হবে।`
  2. UI (`packages/app/src/pages/Purchases.tsx`) একই শর্ত আগেই দেখায় — বাকি + সাপ্লায়ার নেই হলে
     “সংরক্ষণ করুন” নিষ্ক্রিয় ও কারণ লেখা থাকে, তাই বাটন কখনো অন্ধভাবে ব্যর্থ হয় না।
  3. পুরোনো ডেটাবেজে এমন ক্রয় থাকলে `reconcile()` এখন সেগুলো নিট পাওনায় ধরে এবং আলাদা
     সতর্কতা সারি দেয় (`সাপ্লায়ার ছাড়া বাকি ক্রয় … ঠিক করা দরকার`) — লুকানো পার্থক্য নয়।
- **টেস্ট:** `invariants.test.ts` (ডিফল্ট পথ), `security-audit.test.ts` (পুরোনো ফিক্সচার এখন পূর্ণ পরিশোধ করে)।
- **যাচাই:** AUTOMATED PASS।

### F-5 — `reconcile()` বাতিল বিক্রয় গুনত

- **কী পাওয়া গেল:** একই দিনে একটি বিক্রয় বাতিল করলে জার্নাল রিভার্স হতো কিন্তু `reconcile()`-এর

- **পরিবর্তন:** `accounting.ts` `reconcile()` — দুই কুয়েরিতে `status <> 'voided'`।
- **টেস্ট:** `invariants.test.ts` (`assertLedgerHealthy` প্রতিটি টেস্টে চলে, বাতিল-সহ)।
- **যাচাই:** AUTOMATED PASS।

### F-6 — অস্তিত্বহীন ইউজারনেমে ব্রুট-ফোর্স খোলা

- **কী পাওয়া গেল:** ভুল পাসওয়ার্ডের কুলডাউন শুধু বিদ্যমান ইউজারের জন্য কাজ করত; যে ইউজারনেম নেই
  তার জন্য ব্যর্থ লগইন **কখনো গোনা হতো না**, আর উত্তরও (`ইউজারনেম বা পাসওয়ার্ড সঠিক নয়`) সাথে সাথে
  ফিরত — সময় দেখেই বোঝা যেত কোন অ্যাকাউন্ট আছে।
- **পরিবর্তন:** `auth.ts` `login()` — অজানা ইউজারনেমেও (ক) ডামি salt/hash দিয়ে সমান scrypt কাজ
  (সময়-ভিত্তিক অনুমান বন্ধ), (খ) `registerLoginFailure()` (একই কুলডাউন), (গ) `auth.login_failed` অডিট।
- **টেস্ট:** `packages/core/test/auth-lock.test.ts` → “counts failures for usernames that do not exist
  and audits every one” (৫ ব্যর্থতার পর ৬ষ্ঠ চেষ্টায় কুলডাউন বার্তা + ৫টি অডিট সারি)।
- **যাচাই:** AUTOMATED PASS।

### F-7 — Electron ৩৮ (high advisory) থেকে আপগ্রেড

- **কী পাওয়া গেল:** `npm audit` → `electron` high (offscreen paint callback use-after-free,
  `<= 42.11.15`), সাথে বিল্ড-টুলচেইনে `extract-zip` high।
- **পরিবর্তন:** `electron` ৩৮.৮.৬ → **৪৩.৮.৭** (advisory-এর বাইরে, সমর্থিত লাইনে)।
  আপগ্রেডের পরে `npm audit --omit=dev` → **০** (প্রোডাকশন ডিপেন্ডেন্সিতে কোনো ভুলনারেবিলিটি নেই);
  সম্পূর্ণ ট্রি-তে high/critical **০**, moderate ১৫ (সবই `electron-builder` বিল্ড-টুলচেইন:
  `app-builder-lib`, `dmg-builder`, `ejs`, `glob`, `minimatch`, `rimraf`, `temp`, `extract-zip` — ইনস্টলারে
  গ্রাহকের কাছে পৌঁছায় না, বিল্ড-টাইমে চলে)।
- **যাচাই:** BUILD PASS (typecheck + ২৬৩ টেস্ট + দুই অ্যাপের বিল্ড সবুজ, `npm run verify`)।
- **সীমা (গোপন নয়):** স্যান্ডবক্সে Electron রানটাইম চালানো যায় না — তাই ৪৩-এ **রানটাইম** ধোঁয়া-পরীক্ষা
  এখানে `BLOCKED`। Windows ইনস্টলার ও প্রথম চালু যাচাই রিলিজ ওয়ার্কফ্লো + ম্যানুয়াল QA-তে।

(বা ড্যাশবোর্ডের স্কেলিটন) আঁকে কি না যাচাই করে। আগে রিটেইল UI-এর **শূন্য** রেন্ডারার টেস্ট ছিল;
এখন ইমপোর্ট-ভাঙা পেজ বা খালি শেল সিআই-তেই ধরা পড়বে।
