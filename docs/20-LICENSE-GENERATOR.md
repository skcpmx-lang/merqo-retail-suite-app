# সাউদা লাইসেন্স জেনারেটর — পণ্য নথি (v1.1.1)

> এই নথিটি **MERQO-র ভেতরের পণ্য** সাউদা লাইসেন্স জেনারেটরের নিজস্ব আর্কিটেকচার, নিরাপত্তা মডেল,
> ওয়ার্কফ্লো ও সীমাবদ্ধতা বর্ণনা করে। গ্রাহকের অ্যাপ (`Sauda Retail Suite`) একটি আলাদা পণ্য এবং
> একটি আলাদা ইনস্টলার — এই নথি তার লাইসেন্সিং চুক্তিকে ব্যাখ্যা করে, কিন্তু তার UI বর্ণনা করে না।

## ১. এটি কী এবং কেন আলাদা পণ্য

জেনারেটর হলো MERQO-র প্রশাসনিক কনসোল, যা গ্রাহকের মেশিনে তৈরি হওয়া **ডিভাইস রিকোয়েস্ট ফাইল**
(`.sauda-device`) পড়ে, Ed25519 প্রাইভেট কী দিয়ে একটি **স্বাক্ষরিত লাইসেন্স** তৈরি করে এবং সার্টিফিকেট
(HTML/PDF/প্রিন্ট) দেয়। এটি ইন্টারনেট, ক্লাউড বা কোনো SaaS-এর উপর নির্ভর করে না।

আলাদা পণ্য হিসেবে এর নিজস্ব:

| দিক | অবস্থা |
|---|---|
| আর্কিটেকচার | `src/domain.ts` (Electron-মুক্ত নিয়ম), `src/main.ts` (হালকা Electron শেল), `renderer-src/` (React 19) |
| নেভিগেশন | ১২টি পাতা, ৩টি গ্রুপ (প্রধান · লাইসেন্সিং · প্রশাসন) |
| ইনস্টলার | `Sauda-License-Generator-1.1.1.exe` (NSIS, বাংলা শর্টকাট) |
| টেস্ট | ৩০টি নিজস্ব টেস্ট (ডোমেইন ১৫, ইন্টিগ্রেশন ১০, রেন্ডারার ৫) + স্ট্যাটিক অডিট স্ক্রিপ্ট |
| নথি | এই ফাইল + `04-licensing.md` + `FINAL_UI_UX_AUDIT_V111.md` |

## ২. স্তর ও ডেটা ফ্লো

```
renderer-src (React)  ──window.licgen.invoke──▶  preload.ts (contextBridge)
                                                        │ ipcRenderer.invoke('licgen:invoke')
                                                        ▼
                                              main.ts  (রাউট টেবিল, ফাইল ডায়ালগ, প্রিন্ট)
                                                        │
                                                        ▼
                                              domain.ts (স্টোর, স্বাক্ষর, যাচাই, রিপোর্ট)
                                                        │
                                                        ▼
                                   %APPDATA%/Sauda License Generator/  (store.json, ledger.jsonl)
```

- **রেন্ডারারে Node নেই** — `node:fs`, `electron`, `@sauda/core` কিছুই ইমপোর্ট করা যায় না; অডিট স্ক্রিপ্ট এটি বাধ্যতামূলকভাবে যাচাই করে।
- **প্রতিটি IPC রাউট** `{ok:true,data}` অথবা `{ok:false,error}` ফেরত দেয়; ত্রুটি বার্তা বাংলায়।
- **CSP** রেন্ডারার `index.html`-এ নির্ধারিত; `nodeIntegration` বন্ধ, `contextIsolation` চালু (অডিটে যাচাই হয়)।

## ৩. ফাইল ও অবস্থান

| ফাইল | কী থাকে | কোথায় |
|---|---|---|
| `store.json` | কাস্টমার, লাইসেন্স রেকর্ড, সেটিংস (Store v2) | `userData` |
| `ledger.jsonl` | শুধু-যোগ (append-only) ঘটনা লগ: issued / reissued / revoked / verified / backup | `userData` |
| `config.json` | শুধু **কী ফাইলের পাথ**, কী নিজে নয় | `userData` |
| `.sauda` | গ্রাহককে দেওয়া স্বাক্ষরিত লাইসেন্স ফাইল | অপারেটর যেখানে সংরক্ষণ করে |

স্টোর লেখা **atomic** (`.tmp` → rename)। স্টোর নষ্ট বা অনুপস্থিত হলে অ্যাপ খালি স্টোর নিয়ে চলে,
কিন্তু পুরোনো ফাইল মুছে ফেলে না — ব্যাকআপ থেকে রিস্টোর করা যায়।

## ৪. নিরাপত্তা মডেল (কী)

1. **প্রাইভেট কী কখনো** অ্যাপের ভেতরে প্যাকেজ হয় না, রিপোজিটরিতে থাকে না, ইনস্টলারে যায় না, UI-তে দেখানো হয় না, কোনো রিপোর্ট এক্সপোর্টে আসে না, এবং কপি করার কোনো বাটন নেই।
2. কী শুধু **রানটাইমে ফাইল থেকে লোড** হয় (`key.load`); লোড হওয়ার পর `key.status` কেবল `{loaded, keyId, publicKeyB64, path}` ফেরত দেয়।
3. **স্বাক্ষরের পরপরই স্ব-যাচাই** (`check`) হয় পাবলিক কী দিয়ে; ব্যর্থ হলে কোনো ফাইল লেখা হয় না এবং কোনো রেকর্ড তৈরি হয় না।
4. **স্বাক্ষরিত পেলোড সম্পাদনাযোগ্য নয়।** পরিবর্তন দরকার হলে **রি-ইস্যু** (নতুন কী) অথবা **প্রত্যাহার** — সরাসরি এডিটের কোনো পথ নেই।
5. **প্রত্যাহার** করলে কারণ বাধ্যতামূলক, এবং পুরোনো রেকর্ড অপরিবর্তিত থাকে; লেজারে নতুন এন্ট্রি যোগ হয় (পুরোনো লাইন কখনো মুছে যায় না)।
6. **ব্যাকআপে প্রাইভেট কী যায় না** — ব্যাকআপে থাকে স্টোর, লেজার ও সেটিংস।

> সীমা: জেনারেটর যেখানে চলে, সেই মেশিনের ফাইল-সিস্টেমেই কী থাকে। OS-স্তরের সুরক্ষা (BitLocker, ACL, আলাদা অফলাইন মেশিন) MERQO-র দায়িত্বের বাইরে নয়, কিন্তু অ্যাপ নিজে তা করতে পারে না। ANTIVIRUS/EDR হুমকি মডেল `FINAL_SECURITY_AUDIT.md`-এ।

## ৭. যাচাইকরণ ও স্বয়ংক্রিয় পরীক্ষা

`npm run verify` চালালে: ৩ প্যাকেজের টাইপচেক → ২২৯টি টেস্ট (২১ ফাইল) → রিটেইল UI ওয়্যারিং অডিট →
**জেনারেটর ওয়্যারিং অডিট** → আইকন → দুই অ্যাপের বিল্ড → সিক্রেট স্ক্যান।

জেনারেটর অডিট (`scripts/audit-license-generator.mjs`) যা বাধ্যতামূলকভাবে ধরে:

- UI যে IPC রাউট ডাকে তা মেইনে **নিবন্ধিত** না থাকলে fail (ডেড বাটন প্রতিরোধ);
- নিবন্ধিত কিন্তু UI-তে অপ্রয়োগযোগ্য রাউট = warning (অরফ্যান হ্যান্ডলার);
- preload-এর চ্যানেল ও main-এর `ipcMain.handle` চ্যানেল মিলছে কি না;
- রেন্ডারারে `node:`/`electron`/`@sauda/core` ইমপোর্ট এবং `nodeIntegration`/`contextIsolation` পতাকা;
- প্রাইভেট কীর যেকোনো রেফারেন্স (রেন্ডারার ও preload);
- অস্তিত্বহীন CSS ক্লাস/আইকন ব্যবহার (undefined class/icon = fail);
- ১২টি পাতা সবই `App.tsx`-এ মাউন্টেড এবং প্রতিটি নেভ আইটেমের পাতা আছে;
- UI স্ট্রিং-এ অপ্রত্যাশিত লিপি (ভুল বর্ণমালা ঢুকে পড়া)।

> **যা এখনো স্বয়ংক্রিয়ভাবে যাচাই হয় না:** Electron রানটাইম আচরণ, Windows ইনস্টলার (UAC/শর্টকাট),
> ফাইল ডায়ালগ, প্রিন্টার আউটপুট, এবং চোখে দেখার ভিজ্যুয়াল গুণ — এগুলো `FINAL_QA_CHECKLIST.md`-এর
> ম্যানুয়াল ধাপ, এবং স্যান্ডবক্সে **BLOCKED**।

## ৮. সীমাবদ্ধতা (সৎ তালিকা)

- **অফলাইন রিভোকেশন আংশিক** — গ্রাহকের মেশিন ইন্টারনেটে না গেলে প্রত্যাহার স্বয়ংক্রিয়ভাবে পৌঁছায় না; শুধু নতুন যাচাই/রি-ইস্যুতে বোঝা যায়।
- **কোনো মাল্টি-ইউজার/রোল নেই** — জেনারেটর এক অপারেটরের জন্য; মেশিনের OS একাউন্টই সীমা।
