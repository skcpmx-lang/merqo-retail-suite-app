# V1.1.5 — issue register

Every defect found in the v1.1.5 audit, with severity, evidence, fix and the test that now holds the
line. **Nothing is marked fixed without a test that fails on the old behaviour.** Severity is about
what a shop would experience, not about how hard the fix is.

Severity: `S1` money/data loss · `S2` wrong behaviour a cashier can hit · `S3` degraded behaviour ·
`S4` hygiene.

| A-12 | **S2** | POS / pricing | `products.min_sale_price` is **per primary unit**, but the POS compared it with the price **per chosen unit**. Any product with a floor could not be sold in a smaller unit at all — 250 g of ৳120/kg rice (floor ৳100/kg) was refused as "সর্বনিম্ন বিক্রয়মূল্য 100.00 টাকা" although the line was 25% above the floor. A grocery selling loose rice, sugar, oil or dal hits this every day. | Reproduced on a fresh DB: product priced per kg with a floor, sold by the gram → refused. | Two different units compared as if they were one; the conversion existed for the price but not for the floor. | The floor is converted into the sold unit with the same integer `roundDiv` used for the price (the price conversion was also made integer), and the error names the floor per sold unit. | `sale-price-floor-v115.test.ts` (6 tests; 4 fail with the fix reverted). | **FIXED** |
| A-13 | **S2** | POS / serial & IMEI tracking | Serials were matched by string alone. `serial_numbers` is `UNIQUE(product_id, serial)`, so selling one product marked **every** product's row with that serial sold (a unit silently disappears from another product's tracked stock), and a serial belonging to product A was accepted on a line for product B. In a multi-line cart the quantity guard also used a cursor that advanced only for lines carrying serials, so the second product was checked against the first product's quantity and a legal sale was refused. | Read `markSerialsSold` (no `product_id` in the `WHERE`); reproduced all three on a test DB. | The registry is keyed per product, but the sale path treated serials as globally unique. | `markSerialsSold` takes an optional `productId` and scopes the update; the sale path passes the line's own product and indexes the correct line; an ambiguous unscoped update (a legacy caller hitting two rows) is reported instead of guessed. | `sale-serials-v115.test.ts` (6 tests; 2 fail with the scoping reverted, 1 with the cursor bug restored). | **FIXED** |
| A-14 | **S1** | Backup / restore | A restore deleted the WAL sidecars and renamed the new file over the live database in one step. On Windows that rename fails when anything still holds the file (antivirus, the search indexer, a backup agent), and v1.1.4 then left the shop with **no database at the live path** — the data only in `<live>.restoring` and the safety backup, recovered by hand at the worst possible moment. | Read `restoreBackup`; the failure mode is the documented Windows rename behaviour, and the previous code had no rollback branch. | The swap was treated as atomic across filesystems it is not atomic on. | Two-step reversible swap: live → `<live>.previous`, temp → live, and on failure the previous file is moved back. `.previous` is deleted only after the restored database has been reopened and logged, so the previous data exists until the new one is proven. | `restore-safety-v115.test.ts` "a successful restore" (no `.previous`/`.restoring` left, safety backup valid) + three refusal cases that leave the live file byte-identical. | **FIXED** |
| A-15 | **S1** | Backup | Backup file names had **one-second** resolution, so two backups in the same second overwrote each other — including the manifest. ## How to read a "FIXED" row

- The **evidence** column says how the defect was observed, not how it was fixed.
- The **regression test** column names a file and, where useful, the test. For A-01 the fix was
  reverted locally and the two relevant tests failed, then re-applied and they passed — that is the
  standard applied to every S1/S2 fix in this register.
- Anything that cannot get that evidence stays `OPEN` or `ACCEPTED LIMITATION` and is disclosed in
  the release notes and `V1.1.5_KNOWN_LIMITATIONS.md`.
