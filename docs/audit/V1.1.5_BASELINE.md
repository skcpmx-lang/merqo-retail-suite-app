## 3. Environment limitations (stated up front)

| Capability | Availability here | Consequence |
| --- | --- | --- |
| Linux x64 container, Node 22 | available | all unit/integration tests, typecheck, builds, static audits |
| GitHub Actions `windows-latest` | available | real Windows test execution, real NSIS packaging, installer verification, publication |
| Windows 10/11 desktop VM (interactive, printer, scanner, two PCs, DPAPI user profile) | **not available** in this environment | Phase 6 VM evidence cannot be produced here; the gate stays BLOCKED until the owner runs the documented procedure on real hardware |
| GUI interaction (Electron window, screenshots) | not available | UI verification is static + automated screen-level checks; visual confirmation is owner-side |
| Authenticode certificate | none, by policy | installers ship unsigned; "Unknown publisher"/SmartScreen is expected and disclosed |

This baseline is honest about the gap: automated and Windows-runner evidence is real; **interactive
Windows desktop, two-PC LAN and hardware evidence is not obtainable here** and must not be reported as
passed.

## 4. Known limitations carried in from v1.1.4

1. **Revocation is offline** — a revoked licence keeps working until expiry on an already-activated PC.
2. **v1.1.3 clients must be upgraded and re-paired** (the shared-token channel was removed deliberately).
3. **No offline trading on a Client PC** by design.
4. **Licence-signing key rotation** is a manual, documented procedure.
5. **Unsigned installers**, accepted by the owner.
6. **Physical/two-PC/hardware tests** — pending owner testing, recorded as such.

## 5. Carry-over observations from the v1.1.4 release work (inputs to this audit, not yet verified as defects)

| Ref | Observation | Status at baseline |
| --- | --- | --- |
| C-1 | `EventStreamHub.open()` has no "stopping" guard: a request that arrives while the main server is shutting down can still register a stream after `closeAll()` | suspected, needs a test that proves it |
| C-2 | A flaky `windows-latest` failure in v1.1.4 (`sse-v114` "closes every stream when the server stops", 4 s wait) was fixed by widening the wait budget; the underlying race was not proven | test hardened; root cause unproven |
| C-3 | better-sqlite3 ships prebuilds for every platform inside both installers (linux/darwin/win32-arm64), inflating the installers | confirmed by the v1.1.4 payload annotations; size impact to be measured |
| C-4 | The release workflow and release tooling hard-code `1.1.4` (artifact names, notes path, release title) | confirmed by inspection at baseline (see risk register R-01) |
| C-5 | 29 `react-hooks/exhaustive-deps` suppressions across the Main App renderer | to be triaged: genuine load-once effects vs stale-closure risk |
