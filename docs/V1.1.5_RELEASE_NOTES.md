## What’s new

_Being completed from the v1.1.5 audit; every entry below will name the fix and its regression test._

This release is mostly about **trusting the numbers**. Six defects were found by reading the code
rather than by a failing test window, and each one now has a test that fails if it comes back.

**Sales you could not make, now possible**

- A product with a minimum price could not be sold in a smaller unit at all: 250 g of rice priced at
  ৳120/kg with a ৳100/kg floor was refused as "below the minimum". The floor is now compared in the
  unit you are actually selling, and the error message says so ("৳0.10 per gram").
- Everything else about the floor is unchanged: selling genuinely below it is still refused unless
  your permission allows it.

**Stock and serial/IMEI records that now stay correct**

- A stock adjustment or write-off is all-or-nothing. Before, if the accounting posting failed (a
  ledger account missing, for example), the stock moved but the books did not — and no report would
  ever show it.
- A sold IMEI/serial is recorded against **its own product**. Previously a serial could land on the
  wrong product's line, and two products sharing a serial string could both be marked sold. The
  quantity check for a cart with several products also used the wrong line, which could refuse a
  legitimate sale.

**Backups you can actually rely on**

- Two backups taken in the same second no longer overwrite each other. This mattered most during a
  restore: the automatic pre-restore safety backup could replace the very file you were restoring,
  and the shop would appear to "restore" its current state.
- A restore can no longer leave you without a database. The swap is reversible: if Windows refuses to
  move the file (antivirus, search indexer), your existing database is put back and the message tells
  you where the files are.
- Restoring a truncated or foreign file still refuses before touching anything, and a Client PC's
  database still cannot be restored over the shop's.

**Everyday use**

- **Keyboard throughout.** Dialogs keep Tab inside them and give focus back when they close; table
  rows open with Enter or Space; tabs move with the arrow keys; the POS shows its shortcut legend
  (F2 search, F3 hold, F4 held list, F8 payment). A till driven without a mouse is now first-class.
- **Better readability where it matters.** A stronger focus ring, sticky column headers on long
  lists, money columns that line up digit for digit, and print rules that print the page rather than a
  screenshot of it.
- The About/sidebar version line no longer falls back to a hard-coded number: it shows the real
  version, or nothing, never a wrong one.

**Sauda License Generator**

- Licence lists can be opened from the keyboard, with the same focus ring as the Main App.
- Release tooling derives every version-dependent name from the application manifest, and a tag that
  does not match the manifest fails the build before anything is packaged — a release can no longer be
  mislabelled or carry the previous version's installers.

**Faster lists and reports.** On a database with 300,000 sales, opening the sales list for a month
went from 27 ms to 0.03 ms and the daily report from 67 ms to 27 ms (measured, see
`docs/V1.1.5_PERFORMANCE.md`). This is done with database indexes, plus a change to how the date
filters are written.

**A gift card and its statement always agree.** Correcting a card's balance, or putting money back
on one, now writes the balance and the transaction line (with the reason and the user) together —
previously a failure in between could leave a card worth an amount its own history could not explain.

**Cash and the books stay in step.** A cash-in/cash-out entry and its accounting entry are now
written together: if the books reject it (a changed chart of accounts), the drawer no longer records
money the ledger never saw. The same applies to a journal entry and its lines — an entry can no longer
be saved with only part of its lines.

**Device pairing cannot be sabotaged from the network.** If a pairing attempt fails — wrong shop's
licence, no free seat — the code the Main PC showed is no longer used up, so pairing keeps working.
Enrolling, approving and revoking a device are now single steps: a failure leaves the device exactly
as it was instead of half-registered or half-revoked.

**Smaller installers.** The installers no longer carry database binaries for macOS, Linux and
Windows arm64 that this product cannot run on (about 14 MB uncompressed). Nothing about how the app
works on Windows changes.

**Your data is not moved.** The database goes from schema 6 to schema 7, and the only change is
**indexes** — no table, no column, no row. A `.pre-migration-v6-to-v7-*.bak` copy of the database is
written next to it before the upgrade, and v1.1.4 licences keep working. If you ever need to go back
to v1.1.4, restore that copy (or your backup) first — v1.1.4 cannot read a v7 database.

## Installation

1. Run `Sauda-Retail-Suite-Setup-1.1.5.exe` on the **Main PC**.
2. Complete Setup (business details, admin user).
3. Activate the shop licence (Settings → Licence) using the file issued by
   `Sauda-License-Generator-1.1.5.exe`.
4. For Client PCs: Settings → Network → enable Server Mode, and allow the Windows firewall prompt for
   **Private** networks only.
5. On each Client PC: install the same file, choose **Client PC**, enter the Main PC's address or scan
   the pairing QR, then approve the pending device on the Main PC (Settings → Devices).

## Upgrading from v1.1.4

1. **Back up first** on the Main PC (Shop → Backup) and copy the file off the machine. Note the
   counts: products / sales / customers / total dues.
2. Close the app on every PC.
3. Install v1.1.5 on the Main PC and start it. The existing database is upgraded in place; a
   pre-upgrade copy is written automatically.
4. Confirm the counts match, then open a sale, a purchase and a report.
5. Client PCs: install v1.1.5 and reconnect. Licences issued for v1.1.4 remain valid.
6. Keep the v1.1.4 installer and the backup until you are satisfied.

## Backup

- Main PC: Shop → Backup (manual) and Settings → Backup schedule (automatic), written under
  `%APPDATA%\Sauda Retail Suite\backups`.
- A Client PC refuses backup/restore by design.
- Copy backups off the Main PC regularly — same-disk backups do not survive a disk failure.

## Rollback (v1.1.5 → v1.1.4)

1. Quit the app on all PCs (tray → Quit) to release the database lock.
2. Uninstall v1.1.5 (the data directory is preserved).
3. Reinstall v1.1.4.
4. v1.1.5 upgrades the database to schema 7 (indexes only). v1.1.4 cannot open it, so restore the
   copy v1.1.5 wrote automatically — `sauda.db.pre-migration-v6-to-v7-*.bak` next to the database —
   or your own backup, into `%APPDATA%\Sauda Retail Suite\data\sauda.db`, and delete the `-wal` /
   `-shm` sidecars left by v1.1.5.
5. Reinstall v1.1.4 on each Client PC.

## Verify your download

```bat
certutil -hashfile Sauda-Retail-Suite-Setup-1.1.5.exe SHA256
certutil -hashfile Sauda-License-Generator-1.1.5.exe SHA256
```

Compare both hashes with `SHA256SUMS.txt` on this release page before running the installer. These
builds are **unsigned** — Windows will report an "Unknown publisher" and may show "Windows protected
your PC" on first run: choose "More info" → "Run anyway" only after the hashes match. A mismatch
means the download is corrupt or tampered with; delete it.

## Known limitations

- Client PCs require a working network link to the Main PC; there is no offline trading mode by design.
- **Revocation is offline.** Revoking a licence in the License Generator stops it being exported again
  and marks the record, but a PC that is already activated keeps running until the licence's expiry
  date — the Main App does not contact a server to check.
- Device count is bounded by the licence; no throughput figures are published because none were
  measured on customer hardware.
- The installers are unsigned, so Windows shows “Unknown publisher” / SmartScreen on first run.
- Licence-signing key rotation is a manual, documented procedure.
