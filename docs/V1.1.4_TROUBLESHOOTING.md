# Troubleshooting — Sauda Retail Suite v1.1.4

Practical first aid for a shop in front of a customer. Blunt rules first:

- **Never** delete or rename `%APPDATA%\Sauda Retail Suite\data\sauda.db` to "reset" the app. That is
  the shop's books. Back up first, always.
- The **Main PC is the only place business data exists.** If the Main PC is down, client tills cannot
  sell — that is by design, not a bug to work around.
- When in doubt: quit the app on every PC, copy the backup off the machine, and only then touch
  anything.
- Licence keys and private keys never go in a chat, an email, a screenshot or a support form.

---

## 1. Read this first: where things are

| Thing | Path |
| --- | --- |
| Database | `%APPDATA%\Sauda Retail Suite\data\sauda.db` (+ `-wal`, `-shm` sidecars) |
| Automatic backups | `%APPDATA%\Sauda Retail Suite\backups` |
| Logs | `%APPDATA%\Sauda Retail Suite\logs` |
| Licence file | Settings → Licence (the `.lic` file the shop was issued) |

A database that is **in use** cannot be replaced on Windows: if a copy/move/delete fails with
`EBUSY: resource busy or locked`, something still has the file open. Quit the app from the tray
(not just close the window), then retry.

## 2. "Windows protected your PC" / Unknown publisher

Expected. The v1.1.4 installers are unsigned (owner-accepted policy). Before choosing
**More info → Run anyway**, confirm the SHA-256 of the file you downloaded against `SHA256SUMS.txt`
on the release page:

```bat
certutil -hashfile Sauda-Retail-Suite-Setup-1.1.4.exe SHA256
```

If the hash matches, the file is the one that was built and published. If it does not, delete it and
download again — never "just try it".

## 3. The app will not start

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| Starts, then closes with a message about a newer version | the database was upgraded by a newer build | reinstall that newer build, or restore the pre-upgrade backup (see rollback in the release notes) |
| "foreign key প্রয়োগ করা যাচ্ছে না" / integrity error at startup | database damaged or on a broken disk | copy the whole `data` folder off the machine, then use the app's repair/backup tools; do not run `VACUUM` on a copy that failed an integrity check |
| Nothing happens, no window | leftover process from a crashed session holding the database | Task Manager → end `Sauda Retail Suite`, then start again |
| Second instance opens a read-only view or refuses to start | one Main instance per database is enforced | close the other instance |

## 4. Client PC problems (Main PC / Client model)

| Symptom | First check | Then |
| --- | --- | --- |
| Client shows "no Main PC" | is the Main PC running with Server Mode on? Settings → Network | check the address shown in Settings (IP or host name), and that both PCs are on the same subnet |
| Client cannot connect though the Main PC is up | Windows firewall | allow the app on **Private** networks only — never open the port on public Wi-Fi |
| "certificate pin mismatch" | the Main PC's identity changed (reinstall, restored to different hardware, or someone is impersonating it) | stop. Do not disable pinning. Re-pair deliberately from Settings → Devices after confirming with the owner that the Main PC really was replaced |
| Client stuck as *pending* | approval never happened | approve it on the Main PC: Settings → Devices. A pending PC can do nothing by design |
| Approval refused | licensed capacity reached | revoke a device that is no longer used, or ask for a licence with more capacity. A refused approval consumes no seat |
| Client cannot log in after being revoked | intended | re-approve it on the Main PC if the revocation was a mistake |
| Live lists do not refresh but sales work | the event stream is stalled; events are only hints | the client refetches on the next navigation/sale. If it persists, check the network and the Main PC log |
| Client refuses to back up or restore | by design — clients hold no authoritative data | back up on the Main PC |

## 5. Licence problems

| Message | Meaning | Action |
| --- | --- | --- |
| "licence expired" | expiry date passed | issue a new licence with the License Generator |
| "device does not match" | hardware fingerprint changed beyond tolerance | the licence is bound to the machine; issue a licence for this machine, or move the licence back to the original hardware |
| "signature invalid" | the file was edited, truncated, or produced with a different key | do not hand-edit licence files; re-issue |
| "already activated" | the licence is bound to another machine or was moved | revoke/re-issue rather than copying the file between PCs |

Never weaken signature verification to "make a licence work" — an edited licence file is the one case
where refusing to start is the correct behaviour.

## 6. Printing, scanner, cash drawer

- Wrong paper width or a cut-off receipt: re-select the printer in Settings → Printer; the receipt is
  A4/80 mm/58 mm depending on the profile.
- Barcode scanner types nothing: it must be a keyboard-wedge scanner, focused on a field that accepts
  scans; test it in Notepad first.
- Cash drawer does not open: it opens through the printer's kick-out command; verify the printer is
  set as the default receipt printer and that it supports a drawer port.

## 7. Backups and restore

- Backup runs on the **Main PC only**. Copy the file off the machine — same-disk backups do not
  survive a disk failure.
- Restore: quit every PC → Main PC: Shop → Restore → choose the backup → confirm the counts.
- A restore refuses a database whose role stamp says "client": that file is not a shop's books.
- Before any restore, keep the current `data` folder (zipped) so the operation is reversible.

## 8. Collecting evidence for support

When reporting a problem, include (no licence keys, no private keys):

1. the exact message text and the screen it appeared on,
2. the app version (Help → About) and the Windows build,
3. the last ~200 lines of the newest file in `%APPDATA%\Sauda Retail Suite\logs`,
4. whether this was the Main PC or a Client PC,
5. what happened immediately before (sleep/wake, network change, printer jam, restore, upgrade).

## 9. If a release gate fails on your machine

Do not patch the app on a shop's PC. Roll back to the previous version (release notes, "Rollback"),
restore the pre-upgrade backup, and report the failure with the evidence above. A rollback is always
safer than a hand-edited database.
