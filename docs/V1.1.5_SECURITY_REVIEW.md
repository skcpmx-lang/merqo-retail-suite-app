# V1.1.5 — final security review (second pass)

This is the **second** security pass over the renderer/IPC boundary and the licensing surface, done
after the atomicity work (A-21 … A-29). It records what was re-checked against the final tree, what
was found, and what remains accepted. It does not replace `V1.1.5_SECURITY_NOTES.md`, which describes
how the product protects a shop; this file is about the release itself.

## 1. What was re-checked in the final tree

| Boundary | Check | Result |
| --- | --- | --- |
| `sauda:invoke` (the only IPC channel) | sender frame URL must equal the renderer's own `file://` index — `isTrustedSender()`; anything else is logged and refused with `UNTRUSTED_SENDER` before any route runs | verified |
| Route authorisation | every route declares a permission (`'any'`, a specific permission, or `undefined` for public pre-login routes) and the dispatcher enforces it inside `invokeRoute`; the LAN RPC table uses the same permission strings, so desktop and LAN cannot drift | verified by `scripts/audit-ui.mjs` in the gate |
| Privileged operations | restore requires role `admin` **and** a warning dialog; user management, settings, backup, licence and device routes are permission-gated | verified |
| Path handling | `app.openPath` restricts to backups/exports/data/Documents roots; `app.openDataFolder` takes nothing from the renderer; image import sanitises the basename into `imagesDir`; CSV import opens the file through a native dialog, never a renderer-supplied path | verified |
| **`backup.restore`** | the route accepted any path the renderer named, including the live database, `-wal`/`-shm` sidecars and `.tmp` files | **defect found and fixed — A-29**: `assertRestorablePath()` now refuses the live database, sidecars, half-written files, unknown extensions and missing files before validation runs. The directory stays unrestricted on purpose (USB restore is a real workflow) |
| Renderer hardening | `contextIsolation: true`, `nodeIntegration: false`, `nodeIntegrationInWorker: false`, `webSecurity: true`, `sandbox` where supported, navigation blocked, external links allowlisted to `https:` + known hosts | verified |
| Preload surface | exposes a single `invoke(method, args)` bridge plus a small typed façade; no `require`, no `fs`, no path helpers reach the renderer | verified |
| Error leakage | IPC failures return `{ ok: false, error, code }` with messages written for the shopkeeper; stack traces stay in the log file. LAN errors are mapped to codes (`AUTH_REQUIRED`, `DEVICE_REVOKED`, `PAIRING_INVALID/EXPIRED/USED`, …) rather than internal text | verified |
| Sensitive data exposure | no key material, no password hashes and no session tokens cross the IPC bridge; licence payloads carry public material only | verified |
| Licence surface (Main App) | signature verified before the payload is trusted; expiry + device binding enforced; revocation is offline by design (`V1.1.5_KNOWN_LIMITATIONS.md`) | verified, limitation restated |
| Licence surface (Generator) | private key never leaves the operator's machine; export refuses key material; store + ledger now commit together (A-27); the device request is parsed defensively | verified, one defect fixed |
| Installer contents | `scripts/verify-installer.mjs` gates version metadata, x64 PE, native modules, absence of private-key material and SHA-256; `release.yml` re-downloads the published assets and re-runs the same checks before promoting the draft | verified in the gate |

## 2. Findings from this pass

| ID | Severity | Summary | Status |
| --- | --- | --- | --- |
| A-29 | S2 | The restore route accepted the live database, SQLite sidecars and `.tmp` files as a restore source | FIXED — `assertRestorablePath()`, 3 regression tests |
| A-27 | S2 | Generator store and ledger could disagree, and the ledger is what blocks re-issuing a revoked licence | FIXED — `commitLedgerAndStore()`, 4 regression tests |
| A-21 | S2 | A refused pairing claim burned the shop's code; device writes could half-apply | FIXED — one transaction per operation, 20 regression tests |

Nothing else in this pass produced a confirmed security defect. Items examined and cleared:
`isAllowedExternalLink` (protocol + host allowlist), the tray/menu `shell.openPath` calls (fixed
paths, no renderer input), `display.open` (own process, no IPC surface), `print.*` (listers only),
the LAN client's certificate pinning, and the idempotency store (no user-controlled key reaches SQL
without a bound parameter).

## 3. What is accepted, not fixed, and why

- **Unsigned installers.** Explicitly accepted by the owner. Windows will show "Unknown publisher";
  the checksum file is the integrity control. No certificate secret exists in the repository or the
  workflow.
- **Unencrypted database at rest.** A local shop database on the shop's own disk; encryption would
  need key management that a shop cannot operate safely. File-system permissions + backups are the
  control.
- **Offline licence revocation.** Policy decision (see known limitations), not a defect.
- **No remote/cloud surface.** Nothing to attack remotely except the LAN server, which is TLS +
  device-signature + pinning.

## 4. Verification behind this review

- `npm run verify` on the final tree: 871 tests, 88 files, 0 failed, 0 skipped; typecheck ×3; hooks
  audit; native-artifact audit; audit-trail atomicity guard; UI/IPC wiring audit; secret scan;
  `npm audit --omit=dev` → 0 vulnerabilities.
- `release.yml` re-runs the same gate on `windows-latest`, then verifies the installers, renders the
  notes with measured sizes/hashes, publishes a draft, re-downloads the assets and only then promotes
  it.

## 5. What this review does **not** claim

No penetration test was run against a live two-PC installation; that is part of the deferred
owner testing (T01–T45, **NOT TESTED — OWNER TESTING DEFERRED**). No antivirus or EDR product was
active during testing, so code-signing/SmartScreen and AV-interference behaviour on a customer
machine remains unverified.
