# V1.1.4 — PHASE 3, MILESTONE A: TLS TRANSPORT AND CERTIFICATE PINNING

Date: 2026-11-04 · Design: `docs/V1.1.4_PHASE3_SECURITY_DESIGN.md` §2 · Branch `arena/597b03e9-merqo-retail-suite-app`

## What was built

| File | Change |
|---|---|
| `packages/core/src/net/certificate.ts` | **new** — DER/ASN.1 encoder, self-signed X.509 v3 generator (SANs: localhost, 127.0.0.1, LAN IPv4), SHA-256 fingerprint, constant-time pin check, short fingerprint |
| `packages/core/src/net/rpc.ts` | HTTPS listener when `tls` is supplied (`protocol`, `tls_fingerprint` in the host handle); client `tls: {caPem, fingerprint}` path with an HTTPS request helper that verifies the peer pin and fails closed |
| `packages/core/src/net/index.ts` | exports the certificate module |
| `packages/core/test/tls-v114.test.ts` | **new** — 15 tests |

No new npm dependency was added: Electron guarantees neither `openssl` nor a certificate
authority, so the certificate is built from Node's own crypto primitives and validated by
Node's own parser in the tests.

## Security tests (all passing)

| Test | Property |
|---|---|
| produces a real X.509 certificate | parses with `crypto.X509Certificate`, self-signature verifies, not expired |
| covers loopback/localhost/LAN | `checkIP('192.168.0.10')`, `checkIP('127.0.0.1')`, `checkHost('localhost')`; `10.9.9.9` does not validate |
| fresh serial/key per certificate | two certificates differ |
| ignores malformed IP input | `999.1.1.1` never lands in the SAN |
| exact pin accepted (case/separators ignored) | pinning is usable by humans and machines |
| different pin rejected | `CERT_MISMATCH`, actual fingerprint returned for the operator to compare |
| empty/garbage pin rejected | fail closed, never "trust anything" |
| corrupt certificate handled | no crash |
| pin derived from DER body | matches an independent SHA-256 |
| HTTPS + pinned client | real handshake, sealed envelope, login + call succeed |
| wrong pinned certificate | connection refused (`CERT_MISMATCH`/`OFFLINE`) |
| plaintext HTTP against TLS port | rejected |
| plaintext host without TLS material | still works for tests/loopback |
| wrong shop token over TLS | probe answers but leaks nothing; real call is `UNAUTHORIZED` |

## Limitations and what is deliberately not done yet

- The certificate is **not yet persisted or loaded by the app**; that lands with Milestone B, together
  with the device credential, so the key file, the pin and the pairing QR are introduced in one review.
- No client UI shows the fingerprint yet.
- Nothing here was exercised on Windows or across two physical PCs. Manual steps are in the Phase 3
  design §2 and `docs/V1.1.4_TEST_PLAN.md`.
- The legacy plaintext-transport test path remains for the v1.1.3 compatibility window and is
  explicitly covered by a test so it cannot regress into a silent downgrade.
