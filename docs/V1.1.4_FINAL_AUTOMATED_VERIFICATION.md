## 4. What the automated suite actually proves

1. The v1.1.3 rules still hold: permissions, integer minor units, stock ledger integrity,
   backup/restore validation, licence verification, audit trail (all original suites, unchanged).
2. v1.1.4 Server/Client: TLS with pinning, Ed25519 device signatures, replay protection that
   survives a restart, device-bound sessions, revocation that closes live streams, pending devices
   blocked, single-use pairing codes with expiry, licensed capacity, store isolation.
3. Client PC isolation: the client database can answer nothing about shop data and both backup and
   restore refuse it by role stamp, not by convention.
4. Stale-cart protection: a cart priced before a change is refused at commit and nothing is
   written; the cashier reviews and applies changes explicitly.
5. Event-driven refresh: every screen in scope re-reads through authenticated routes on a hint,
   with coalescing, dedupe, and full refresh on resync/unknown.
6. Electron configuration and IPC trust boundary, asserted against the real source.

## 5. What it does **not** prove

Automated tests run on Linux against a Node transport. They say nothing about: Windows DPAPI
sealing, firewall behaviour, real LAN loss, packaged installers, code signing, SmartScreen,
long-lived streams, revocation latency over a real network, printer/drawer/scanner/display
hardware, or an upgrade from a real v1.1.3 installation. Those are exactly the rows that stay
BLOCKED in the two-PC checklist.
