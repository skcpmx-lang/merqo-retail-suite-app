## 7. Events (PART 15)

Nothing exists beyond same-machine push. Plan: outbox written in the same transaction as the business
operation, SSE stream `/api/v1/events` with `Last-Event-ID` resume, monotonic per-store `sequence`.
Clients must still reconcile via authoritative GETs (explicitly required by PART 15).

## 9. Offline draft behaviour (PART 17)

The POS already refuses to commit while disconnected (routes proxy to a dead host → error), but the
cart is only held in React state: closing the window loses it, and the error message is generic.
Plan: persist the draft locally (encrypted-at-rest not required, no business authority), show an
explicit **Pending/Reconnect** state, revalidate prices/stock on reconnect, and require confirmation
before submitting.

## 11. Performance (PART 27)

No regression gate. Known measured issue: report date filters use `date(col)` and miss
`idx_sales_date` (documented at 200k rows: 20.3 ms vs 5.55 ms). Plan: add a benchmark script with
recorded baselines, and fix the predicate to a half-open range.

## 12. Testing (PART 29–30)

282 tests exist (unit + integration on a real SQLite file, loopback LAN). Missing: concurrency tests,
idempotency tests, device-authorisation tests, event-delivery tests, discovery tests (loopback UDP),
and any load test. Every new subsystem ships with its own tests before the phase is called done.

## 13. Effort and sequencing (what gets built, in what order)

1. **Schema v5 + repositories** (stores, terminals, credentials, sessions, device_licenses,
   idempotency, outbox) — additive, tested.
2. **Device identity + license v2** (payload, verify with backward compatibility, generator issue UI).
3. **Server runtime** (tray, background, auto-start, LEDB health, single-instance guard) + TLS.
4. **API v1** (route table, DTOs, auth/authorization, size limits, idempotency middleware, SSE).
5. **Client mode** (installation role, connection manager, saved servers, discovery, QR, diagnostics).
6. **Approval + device management UI** (pending queue, approve/reject/revoke, capacity counters).
7. **Offline draft + reconnect reconciliation**.
8. **Backup/migration** (destinations, restore wizard, store transfer).
9. **Premium UI pass** on both apps (dark theme, device screen, network screen, generator hierarchy).
10. **Regression + load tests, benchmarks, docs, installers, release candidate** (owner approval gate).

Items 1–3 are foundational; UI polish cannot precede them without rework.
